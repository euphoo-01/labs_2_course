# Ответы на вопросы по WPF (с проекцией на Avalonia UI)

Поскольку проект реализован на кроссплатформенном фреймворке **Avalonia UI**, многие концепции WPF здесь называются иначе (например, `StyledProperty` вместо `DependencyProperty`), но их архитектурный смысл и механизм работы остаются абсолютно теми же. Ниже представлены ответы на классические вопросы по WPF, с отсылками к тому, как это было реализовано в данном проекте.

---

### 1. Что такое Свойства зависимости (Dependency Properties)? Для чего они нужны?
**Свойства зависимости (Dependency Properties, DP)** — это специальный тип свойств в WPF, значение которых не просто хранится в приватном поле, а вычисляется динамически подсистемой свойств на основе множества источников (анимации, привязки данных (Data Binding), стили, темы, наследование значений от родительских элементов).
**Для чего нужны:**
- Экономия памяти (значения по умолчанию хранятся статически и не дублируются для каждого объекта).
- Поддержка двусторонней привязки данных (Data Binding).
- Встроенная поддержка анимаций и изменения значений через стили и триггеры.
- Автоматическое уведомление об изменении значений (PropertyChanged).

### 2. Как создать DependencyProperty?
В WPF свойство зависимости создается в несколько шагов:
1. Регистрация статического поля типа `DependencyProperty` с помощью метода `DependencyProperty.Register`.
2. Создание стандартного CLR-свойства (свойства-обертки), где в геттере вызывается `GetValue()`, а в сеттере — `SetValue()`.
```csharp
public static readonly DependencyProperty MyProperty = 
    DependencyProperty.Register("My", typeof(int), typeof(MyControl), new PropertyMetadata(0));

public int My
{
    get { return (int)GetValue(MyProperty); }
    set { SetValue(MyProperty, value); }
}
```
*(В нашем проекте на Avalonia UI для этого использовался метод `AvaloniaProperty.Register<TOwner, TValue>` и тип `StyledProperty` в элементе управления `StarRatingControl`).*

### 3. Для чего и как используют делегат ValidateValueCallback?
**ValidateValueCallback** используется для **строгой проверки** валидности значения ДО того, как оно будет присвоено свойству. 
- Метод возвращает `true` (значение допустимо) или `false` (значение недопустимо, выбрасывается `ArgumentException`).
- Проверка происходит только на основе самого передаваемого значения, без доступа к экземпляру элемента управления (он статический).
**Как использовать:** Передается как параметр при регистрации DependencyProperty. В нашем проекте метод `ValidateMaxStars` проверяет, чтобы максимальное количество звезд всегда было больше нуля.

### 4. Для чего и как используют делегат CoerceValueCallback?
**CoerceValueCallback** (колбэк принуждения/коррекции) используется для корректировки значения свойства на основе других свойств или внутреннего состояния объекта, если новое значение выходит за логические рамки (при этом исключения не выбрасываются).
- Вызывается *после* ValidateValueCallback, но *до* вызова PropertyChangedCallback.
- Например, если значение выходит за допустимые пределы, метод может "обрезать" его (если передали 15 звезд в рейтинг, а максимум 5 — метод вернет 5).
*(В проекте использованы методы `CoerceMaxStars` и `CoerceValue`, ограничивающие значения ползунков рейтинга от отрицательных значений или значений выше максимума).*

### 5. Какие типы маршрутизируемых событий есть в WPF (поясните каждый)?
Существует три стратегии маршрутизации (Routing Strategies):
1. **Bubbling (Поднимающиеся/Пузырьковые):** Событие возникает на элементе-источнике и "всплывает" вверх по визуальному дереву к корневому элементу (Window). Это самый частый тип (например, `Click` или `MouseDown`).
2. **Tunneling (Туннельные):** Начинаются от корневого элемента (Window) и спускаются вниз по визуальному дереву к элементу-источнику. Обычно имеют префикс "Preview" (например, `PreviewMouseDown`). Позволяют родительским элементам перехватить и отменить событие до того, как оно достигнет цели.
3. **Direct (Прямые):** Подобны обычным событиям .NET. Срабатывают только на том элементе, где возникли, и никуда не маршрутизируются (например, `MouseEnter`).

### 6. Как создать RoutedEvent?
Процесс аналогичен созданию DependencyProperty:
1. Регистрируется статическое поле через метод `EventManager.RegisterRoutedEvent`.
2. Указывается имя события, стратегия маршрутизации (Bubble/Tunnel/Direct), тип делегата обработчика и тип владельца.
3. Создается обычная CLR-обертка `event` с блоками `add` и `remove`, которые вызывают внутренние методы `AddHandler` и `RemoveHandler` соответственно.
*(В проекте в файле `AnimatedCourseCard.axaml.cs` мы создали все три вида (Direct, Bubble, Tunnel), используя метод `RoutedEvent.Register<...>`).*

### 7. Поясните концепцию Command в WPF? В чем ее преимущества?
**Команды (Commands)** — это механизм инкапсуляции пользовательских действий (логики) и их отделения от интерфейса. Они реализуют интерфейс `ICommand`, который предоставляет методы `Execute(object)` (выполнение действия) и `CanExecute(object)` (проверка, можно ли выполнить).
**Преимущества:**
- **Разделение логики и UI (поддержка MVVM):** Кнопка во View просто привязывается к команде во ViewModel.
- **Повторное использование:** Одно и то же действие можно вызвать из контекстного меню, главной панели и через горячие клавиши.
- **Управление состоянием:** Интерфейсные элементы управления автоматически становятся неактивными (Disabled / IsEnabled = false), если `CanExecute` возвращает `false`.

### 8. Как используются команды?
1. В коде (обычно во ViewModel) создается свойство, возвращающее реализацию `ICommand` (в WPF часто используют сторонние реализации типа `RelayCommand`, а в Avalonia - `ReactiveCommand`).
2. В XAML-разметке свойство интерфейсного элемента `Command` привязывается к этой команде: `<Button Command="{Binding SaveCommand}" />`.
3. Опционально передается аргумент через свойство `CommandParameter="{Binding SomeData}"`.

### 9. Как создать RoutedUICommand?
`RoutedUICommand` — это встроенный в WPF класс, представляющий команду, которая маршрутизируется по визуальному дереву в поисках ближайшего обработчика (`CommandBinding`). В отличие от обычных команд MVVM, она также имеет свойство `Text` для описания команды в интерфейсе.
**Как создать (в WPF):**
```csharp
public static readonly RoutedUICommand MyCommand = new RoutedUICommand(
    "Текст команды",    // Text
    "MyCommand",        // Name
    typeof(MyWindow),   // Тип владельца
    new InputGestureCollection() { new KeyGesture(Key.S, ModifierKeys.Control) } // Сочетания клавиш
);
```
Затем в XAML добавляется обработчик: 
`<Window.CommandBindings><CommandBinding Command="local:MyClass.MyCommand" Executed="..."/></Window.CommandBindings>`.

*(Примечание: Avalonia UI отказалась от `RoutedUICommand` в пользу строгой MVVM-архитектуры. Тем не менее, для демонстрации этой концепции (а именно - команды с дополнительными свойствами Text и Name) в нашем проекте в `AppCommands.cs` создан класс `CustomCommand` и статический набор команд, который затем привязан к кнопке `Help`.)*
